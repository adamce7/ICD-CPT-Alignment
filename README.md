# AI Medical Coding and Compliance Tools

This repository contains a suite of AI-powered tools designed to assist with medical coding (ICD-10-CM and CPT) and surgical compliance checks.

---

## 🛠️ AI Service Tools

1. **ICD-10-CM Code Mapping:** Maps patient diagnosis input to the appropriate ICD-10-CM codes.  
2. **CPT Code Mapping:** Maps patient surgery/procedure input to the relevant CPT codes.  
3. **Medical Relevance Checker (ICD/CPT Alignment):** An AI model that correlates a CPT code and an ICD-10-CM code to determine if they are medically relevant to one another (medical necessity validation).  
4. **Surgical Kit Compliance Checker:** Compares a provided surgical kit against a required list (from a dataset or an LLM) for a specific surgery and CPT code, reporting compliance.

## 📁 File Structure and Components

### Code Mapping Files

| File | Description |
|------|--------------|
| **cpt_code.py** | Handles CPT code mapping. Takes patient information (JSON input) and maps it against a local CPT code list CSV file. |
| **icd_code.py** | Handles ICD-10-CM code mapping. Takes patient information (JSON input) and maps it against a local ICD-10-CM code list CSV file. |
| **app.py** | Utilizes a fine-tuned Llama3 model (`m42-health/Llama3-Med42-8B`, approximately 20GB) to check the medical relevance/alignment between CPT and ICD codes. |

---

### `app.py` Key Functions

- **`extract_json(output)`**: Handles the LLM output, extracting and retaining only the useful structured information from the prompt response.  
- **`normalize_icd(icd_input)`**: Deals with inconsistent input ICD code formatting, normalizing it to match the project's data format.  
- **`check_alignment(cpt_code, icd_code)`**: The primary logic function for the medical relevance checker. It validates the input codes, calls the LLM with the formulated prompt, and returns the output.

---

### Surgical Compliance Checker

| File | Description |
|------|--------------|
| **surgery_compliance.py** | Surgical Kit Compliance API. Provides a comprehensive check on whether a provided surgical kit contains all required items and does not include extra items for a given surgery and CPT code. |
| **data/surgery_kits.csv** | Dataset containing a definitive list of required kit items for various surgeries, initially generated by GPT-5 and refined with human input. |

---

### `surgery_compliance.py` Logic

- The system first attempts a deterministic lookup in the `surgery_kits.csv` dataset, matching by **CPT code**, then by **surgery name**.  
- If a match is not found in the dataset, it utilizes the **MedAlpaca-13B model** (`medalpaca/medalpaca-13b`) to infer the required kit items.  
- It then compares the set of provided items against the required items, calculating a **compliance degree (percentage)** and reporting any **missing or extra items**.  
- If the MedAlpaca model fails to load, the system runs in a **"deterministic fallback-only mode."**

## 🧪 Testing and API Access

All main Python files (`cpt_code.py`, `icd_code.py`, `app.py`, and `surgery_compliance.py`) contain a built-in **FastAPI** server for easy testing and integration.

You can launch and test the endpoints locally using tools like **Postman** by running the respective file, for example:

```bash
uvicorn main:app --reload
```
